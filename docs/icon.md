# アイコンの作り方

`src/PasteFence/pastefence.ico`（実行ファイルに埋め込むアイコン）を、
どう作ったか・どう直すかのメモ。

## 中身

| ファイル | 役割 |
| --- | --- |
| `assets/icon/pastefence.svg` | 元の絵。48px 以上で使う |
| `assets/icon/pastefence-small.svg` | 元の絵。16 / 24 / 32px で使う（細部を削った版） |
| `assets/icon/render.mjs` | SVG を PNG にする |
| `assets/icon/pack-ico.py` | PNG をまとめて `.ico` にする |
| `assets/icon/build.sh` | 上の 2 つを順に呼ぶだけ |
| `src/PasteFence/pastefence.ico` | 出来上がり（リポジトリに入れてある） |

絵は全て自分で描いた。外部の画像・アイコン集・フォントは 1 つも使っていない
（図形は四角と角丸だけで、文字も入れていない）。

## 作り直す

```bash
./assets/icon/build.sh
```

同じ入力からは同じバイト列が出る。変わらなければ差分も出ない。

必要なもの:

- `node` と `playwright`（SVG を描くのに Chromium を使う）
- `python3`（標準ライブラリだけ。Pillow などは要らない）

SVG を描く道具が手元に無かったので、**Chromium に描かせて画面を撮る**という
方法を採った。`render.mjs` が SVG を寸法ちょうどの空ページに置き、
背景を透明にしてスクリーンショットを撮る。
`pack-ico.py` はその PNG を読んで `.ico` の構造に組み直す。

## 描いてある物

意味は「**貼り付ける前に一度止める**」。

- 紺色の角丸（`#1B3A5C`）… アプリの土台
- 白いクリップボード（`#FFFFFF`）… コピーした内容
- 琥珀色のクリップ（`#E9A13B`）… 「ここで一度止める」合図
- 紺色の四角 3 つ… 伏せ字 ■■■
- 薄い線（`#BDCBD9`）… 伏せずに残る普通の文字（48px 以上のみ）

色を変えたいときは、SVG の中のこの 4 つの色を書き換えて `build.sh` を実行する。

## 見た目

**256×256**（`pastefence.svg`）
紺色の角丸四角が全面を占める。その中央に、縦長の白いクリップボードが 1 枚。
クリップボードの上辺からはみ出す形で、琥珀色の横長の丸い留め具が 1 つ乗っている。
白い面には横書きの 3 行があり、上段は細くて薄い灰青色の線（＝普通の文字）、
中段は紺色の正方形が 3 つ等間隔に並んだ太い行（＝伏せ字 ■■■）、
下段はまた薄い灰青色の線で、上段より短く途中で終わっている。
伏せ字の行だけが他の行より背が高く濃いので、真ん中の 1 行が隠されていると分かる。

**16×16**（`pastefence-small.svg`）
同じ形から薄い線 2 本を捨てたもの。紺色の角丸が 16px 全面、その上に
白いクリップボードが 10×11px、上に琥珀色の留め具が 4×2px。
白い面の中央に紺色の 2×2px の点が 3 つ、1px ずつ空けて横に並ぶ。
線は全て整数ピクセルに乗るので、輪郭はぼやけない。
遠目には「白い紙に濃い破線が 1 本、上にオレンジの留め具」と読める。

## 寸法ごとの絵の使い分け

`.ico` には 16 / 24 / 32 / 48 / 64 / 128 / 256 の 7 枚を入れてある。

- **48px 以上** … `pastefence.svg`（薄い線 2 本を含む完全な絵）
- **32px 以下** … `pastefence-small.svg`

32px 以下で絵を分けているのは、大きい版をそのまま縮めると
伏せ字 ■■■ の隙間が 1px を切って潰れ、ただの 1 本線に見えてしまうため。
小さい版は座標を全て 3 の倍数にしてあり、`48 ÷ 3 = 16`、`48 ÷ 1.5 = 32` なので
16px と 32px では全ての辺が整数ピクセルに乗る。
24px だけは `48 ÷ 2` で一部の辺が半ピクセルに落ちるため、
縁が 1px ぶん薄くなる。24px が実際に使われる場面は少ないので、
16px の輪郭の鮮明さを優先してこちらは許容した。

## `.ico` の中身

- 16〜128px … BMP（32bit BGRA ＋ AND マスク）。古い API でも確実に読める形式
- 256px … PNG 圧縮のまま。BMP にすると 1 枚で 256KB を超えて無駄に太る
- 合計 107KB

## 確認したこと

Linux 上で確認できる範囲のみ。実機の Windows では未確認。

- `.ico` のヘッダーを読み直し、7 枚ぶんの寸法・ビット数・格納形式が意図どおりか
- 7 枚とも Pillow（別の実装）で読み戻し、元の PNG と **1 ピクセルも違わない**こと
- 各寸法を拡大して目視（上の「見た目」はその結果）
- `.gitattributes` の `*.ico binary` が効いていて、コミット前後でバイト列が変わらないこと
